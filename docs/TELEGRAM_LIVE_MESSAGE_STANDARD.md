# JDSS 실거래 텔레그램 메시지 기준

> 적용 대상: **V3.2.2 실계좌 운영**  
> 첫 거래 기준일: **2026-09-01**  
> 목적: 운영자가 메시지를 보고 실제 주문 상태와 해야 할 행동을 즉시 판단하도록 표현을 통일합니다.

## 1. 기본 원칙

1. 실계좌 운영에서는 `모의주문` 표현을 사용하지 않습니다.
2. `주문 접수`와 `체결 완료`를 명확히 구분합니다.
3. 결과를 확인할 수 없는 주문은 성공으로 추정하지 않습니다.
4. 위험을 늘리는 매수는 운영자 신규매수 잠금과 기존 2단계 승인을 모두 통과해야 합니다.
5. 위험축소 매도, 계좌·원장 대조, 주문 감시는 기존 안전계약을 그대로 유지합니다.
6. 내부 영문 상태값은 필요할 때만 괄호 또는 코드 형식으로 보조 표시합니다.

## 2. 메시지 우선순위

운영 메시지는 다음 순서로 읽히도록 구성합니다.

1. **현재 상태** — 정상 / 확인 필요 / 안전정지
2. **내 돈에 미치는 영향** — 신규매수 가능 여부, 주문 진행 여부
3. **운영자가 할 일** — 승인, 대기, `/order` 확인, `/account` 확인, `/halt`
4. **상세 정보** — 종목, 수량, 가격, 목표비중, 내부 상태

## 3. 주문 상태 표현

| 내부 상태 | 운영자 표시 | 의미 | 운영자 행동 |
|---|---|---|---|
| `CREATED` / `SUBMITTED` / `PENDING` | **실주문 접수** | 토스에 주문이 접수됐지만 체결 완료가 아님 | `/order`에서 진행 확인 |
| `PARTIAL_FILLED` | **실주문 부분체결** | 일부 수량만 체결 | 자동 재주문하지 않고 잔여 상태 확인 |
| `FILLED` | **실주문 체결 완료** | 주문 수량 체결 확인 | `/account`에서 실제 보유와 원장 대조 |
| `REJECTED` | **실주문 거부** | 주문이 접수 또는 체결되지 않음 | 원인 확인 후 새 승인 검토 |
| `CANCELED` | **실주문 취소 확인** | 토스 원주문 상태에서 취소 확인 | 필요 시 최신 조건으로 새 승인 |
| `REPLACED` | **실주문 변경 확인 필요** | 원주문 상태가 변경됨 | `/order`, `/account` 확인 |
| `UNKNOWN` | **실주문 결과 확인 필요** | 전송 결과를 확정할 수 없음 | 재주문 금지, 안전정지·계좌 대조 우선 |

`UNKNOWN`에서는 같은 주문을 다시 보내지 않습니다. 토스 원주문 조회와 JDSS 원장 대조가 끝날 때까지 신규매수를 차단합니다.

## 4. 아침 운용 브리핑

아침 메시지는 10초 안에 다음을 알 수 있어야 합니다.

- 오늘 해야 할 행동
- 현재 목표비중
- 현재 평가액과 투자규모 기준
- 첫 투자 단계가 적용 중이면 현재 단계
- 신규 매수 승인 필요 여부
- 위험축소 또는 안전정지 여부

정상 예시 구조:

```text
[JDSS 실거래 아침 브리핑]
기준일: YYYY-MM-DD

오늘의 결론
- 신규 매수 승인 필요 / 오늘 신규 주문 없음 / 위험축소 진행 중

현재 목표
- QQQ
- TQQQ
- SOXL

실거래 상태
- 실계좌 연결
- 신규매수 잠금 상태
- 계좌·원장 대조 상태
- 첫 투자 단계

운영자 행동
- /today 실제 주문 확인
- /account 실제 계좌 확인
```

## 5. 첫 투자 기간

2026-09-01부터 최초진입 계약은 다음과 같습니다.

- 1단계: 최종 목표의 **50%**
- 2단계: 최종 목표의 **75%**
- 3단계: 최종 목표의 **100%**
- 각 단계 목표 충족 후 다음 단계까지 **최소 3 미국 거래세션**
- 단계 진입은 주문 제출이 아니라 **매수 가능 한도 확대**
- 실제 주문은 `/today`에서 최신 가격·수량을 다시 확인하고 기존 2단계 승인 수행

첫 투자 메시지에는 반드시 `현재 단계`, `현재 누적 한도`, `다음 단계 가능 시점 또는 남은 거래세션`, `지금 주문 필요 여부`를 구분해 표시합니다.

## 6. 안전 메시지

다음 상황에서는 메시지 첫 줄부터 위험 상태가 드러나야 합니다.

- 계좌·원장 불일치
- 주문 결과 불명
- 위험축소 매도 미완료
- 안전정지(SAFE_MODE)
- 신규매수 잠금
- 토스 주문 점검시간
- 주문 가능시간 외

안전정지는 내부 용어만 보여주지 않고 **`안전정지(SAFE_MODE) · 신규매수 차단`**처럼 실제 영향을 함께 표시합니다.

## 7. 메뉴와 연결

일상 운영 흐름은 다음 세 화면을 기준으로 합니다.

```text
/dashboard → /today → /account
```

첫 투자 기간에는 `/onboarding`을 추가 확인합니다. 목표비중·종목상세·점수는 `/portfolio`, 과거검증은 `/backtest`, 긴급 신규매수 중지는 `/halt`를 사용합니다.

## 8. 변경 금지 영역

이 메시지 정리는 다음 계약을 변경하지 않습니다.

- V3.2.2 전략 수학
- 목표비중 계산
- HWM75
- 정수주 주문
- 2단계 매수 승인
- 운영자 신규매수 잠금
- 자동 위험축소 매도
- 계좌·원장 대조
- 결과 불명 시 재주문 금지

코드와 문서는 위 표현 기준을 동일하게 사용하고, 변경 후 텔레그램 포맷·실거래 안전성·문서 계약 테스트를 함께 통과해야 합니다.
