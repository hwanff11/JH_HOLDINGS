# JH_HOLDINGS Telegram 운영 가이드

이 문서는 운영자가 Telegram에서 **자동운용 상태를 확인하고, 자금·최초 시작·긴급정지를 통제하는 방법과 사용자에게 보이는 메시지 표현 기준**을 함께 정의합니다.

- 투자전략 공식 계약: [`JDSS_FINAL_SPEC.md`](JDSS_FINAL_SPEC.md)
- 자동운용 공식 계약: [`JH_AUTO_SPEC.md`](JH_AUTO_SPEC.md)
- 보안·주문 안전: [`infra/SECURITY.md`](infra/SECURITY.md)
- 현재 실제 운영 상태: [`../CURRENT_WORK.md`](../CURRENT_WORK.md)

JH AUTO 1.0.0부터 Telegram의 기본 역할은 **매수 승인기**가 아니라 **자동운용 통제·감시 화면**입니다.

## 1. 평소에는 세 화면만 보면 됩니다

```text
/dashboard   전체 상태·전체 수익률·안전상태
/today       오늘 목표·자동매수/위험축소·차단이유
/auto        기준자금·자동운용비율·현재 허용원금·최초 시작
```

실제 Toss 계좌는 `/account`, 종목별 상세는 `/portfolio`를 확인합니다. 정상 자동운전 중 운영자의 기본 행동은 **없음**입니다.

## 2. 기본 메뉴

| 메뉴 | 용도 |
|---|---|
| `/dashboard` | 전체 자동운용 상태·자금·성과·안전상태 |
| `/today` | 오늘 종목별 목표·자동매수·위험축소·차단이유 |
| `/auto` | 운용 기준자금·자동운용비율·현재 허용원금·최초 시작 |
| `/account` | 실제 Toss 계좌·보유·미체결·매수가능금액 |
| `/portfolio` | QQQ/TQQQ/SOXL 보유·목표·평단·수익률 |
| `/backtest` | JDSS 공식 과거검증 |
| `/halt` | 운영자 긴급 신규 BUY 정지 |
| `/resume` | 운영자 긴급정지/복구 가능 안전상태 해제 검토 |
| `/help` | 전체 기능·장애대응 |

과거 `/onboarding`, 개별 BUY 승인 기능은 호환·비상점검 경로로 남아 있을 수 있지만 **정상 JH AUTO 운영 메뉴에서는 사용하지 않습니다.** 자금투입 50→75→100은 `/auto`가 보여주며 정확한 승격계약은 `JH_AUTO_SPEC.md`가 소유합니다.

## 3. `/dashboard`: 첫 화면

대시보드는 다음 순서로 읽습니다.

1. 현재 상태
2. JDSS / JH AUTO 버전
3. 운용 기준자금·자동운용비율·목표 자동원금·현재 허용원금
4. 자동운용자산·누적손익·누적수익률
5. 투자중/현금·HWM75 현재 위험예산
6. 최초 시작승인·운영자 긴급정지·시스템 임시격리·SAFE_MODE
7. 진행 중 주문
8. 운영자 행동

예시:

```text
[JH_HOLDINGS 자동운용 대시보드]

현재 상태          자동운전 정상
투자전략           JDSS 3.2.2
자동매매           JH AUTO 1.0.0

자동운용 자금
운용 기준자금      $50,000
자동운용비율       20%
목표 자동원금      $10,000
현재 허용원금      $10,000

현재 성과
자동운용자산       $10,438
누적 운용손익      +$438
누적 운용수익률    +4.38%
HWM75 현재 위험예산 $10,438

대표님 행동        없음
```

위 금액은 표시 예시입니다. JDSS 연구 기준 `$50,000`을 실거래 고정한도로 표시하지 않습니다.

## 4. `/portfolio`: 종목별 보유·수익률

전체:

- 자동운용자산
- 누적 운용손익
- 누적 운용수익률
- 현재 투자액
- 현재 허용원금
- HWM75 현재 위험예산

QQQ/TQQQ/SOXL 각각:

- 보유수량
- 목표수량
- 평균단가
- 현재가
- 평가액
- 평가손익
- 보유수익률
- 목표비중

`보유수익률 = 현재 보유분 평가손익 / 현재 보유분 원가`입니다. 종목별 수익률을 더해서 전체 수익률로 사용하지 않습니다.

## 5. `/today`: 오늘 자동운용 관찰화면

`/today`는 사람이 BUY를 누르는 승인화면이 아닙니다.

필수 표시:

- 전체 누적수익률·누적손익
- 현재 미국장 상태
- 각 종목 `현재수량 → 목표수량`
- 각 종목 보유수익률
- 자동매수 또는 위험축소 필요 수량
- 신규 BUY가 차단돼 있다면 가장 중요한 이유
- 운영자 행동

정상 AUTO 상태에서는 `대표님이 별도로 개별 BUY를 승인할 작업은 없습니다.`를 표시합니다.

## 6. `/auto`: 자동운용 통제센터

`/auto`에서 확인하는 값:

- 운용 기준자금
- 자동운용비율
- 목표 자동원금
- 현재 허용원금
- 자금개방 단계
- 최초 시작승인 여부
- HWM75 현재 위험예산
- 최근 자동주문·차단상태

직접 입력 예:

```text
/auto capital 50000
/auto ratio 20
/auto start
```

모든 자금·비율·최초 시작 변경은 **2단계 확인**입니다. 첫 명령은 검토화면만 만들고 최종 확인에서 운영설정을 변경합니다.

확인버튼은 1회성이며 만료·재사용·서버 재시작·설정 revision 변경 시 거부하고 새 검토를 요구합니다.

## 7. 최초 시작 절차

최초 시작은 **배포와 다른 행위**입니다.

```text
배포 완료
→ /dashboard 상태 확인
→ /auto에서 운용 기준자금 설정
→ /auto에서 자동운용비율 설정
→ /account에서 실제 계좌·미체결·매수가능금액 확인
→ /auto start
→ 2단계 최종 확인
→ 해당 callback 주문 0건
→ 다음 독립 안전주기에서 전체 조건 재검증
→ 조건 충족 시에만 첫 AUTO BUY 가능
```

최초 시작 전 화면은 다음 의미를 분명히 보여야 합니다.

```text
현재 상태             최초 시작 대기
최초 시작승인         미승인
현재 허용원금         $0
최고 평가액           시작 전
HWM75 현재 위험예산   시작 전
실제 신규 BUY         차단
대표님 행동           자금·계좌 확인 후 /auto start 검토
```

과거 모의원장의 `$50,000` HWM을 현재 실거래 위험예산처럼 보여주지 않습니다.

최종 시작확인 뒤에도:

```text
최초 시작승인 완료
현재 허용원금         1단계 기준
이 확인 처리의 주문   0건
다음 행동             독립 안전주기 재검증
```

으로 표시합니다.

## 8. 자금변경

### 운용 기준자금 또는 자동운용비율 증가

적용 전 현재값·변경값·예상 목표 자동원금을 보여줍니다.

```text
자동운용비율 변경
현재 20% → 변경 50%
목표 자동원금 $10,000 → $25,000
추가 원금은 공식 자금개방 단계로 점진 적용됩니다.
```

설정변경 callback 자체가 BUY를 열거나 주문을 제출하지 않습니다. 설정변경 중에는 시스템이 신규 BUY를 잠그고 격리하며, 다음 독립 안전주기에서 계좌·원장 대조 후 정상복귀를 판단합니다.

### 감액

```text
자동운용비율 감소
목표 자동원금 $25,000 → $10,000
위험감소는 단계대기 없이 새 목표에 반영됩니다.
```

감액은 위험축소 SELL을 우선합니다.

## 9. `/halt`: 운영자 긴급정지

`/halt`는 신규 BUY를 즉시 막는 **운영자 durable latch**입니다.

표시해야 할 내용:

- 신규 BUY 차단
- 가능한 미체결 BUY 취소 시도 상태
- 위험축소 SELL·주문감시·계좌대조 지속 여부
- 시스템 자동해제 불가
- 복구 시 `/resume` 필요

배포·서비스 재시작·정상조회만으로 `/halt`를 자동해제하지 않습니다.

## 10. `/resume`: 복구 검토

`/resume`은 최초 시작명령이 아닙니다.

```text
/resume
→ 2단계 확인
→ 운영자 halt latch 확인
→ 미체결/UNKNOWN 확인
→ 계좌·원장 대조
→ SAFE_MODE 복구 가능여부 확인
→ 조건 충족 시 운영자 latch 해제
→ 주문은 제출하지 않음
```

이후 다음 독립 안전주기에서 자동실행 조건을 다시 판단합니다.

## 11. 주문·장애 상태 표현

| 내부 상태 | 운영자 표시 | 기본 행동 |
|---|---|---|
| 정상 | 자동운전 정상 | 없음 |
| 시작 미승인 | 최초 시작 대기 | `/auto` 확인 |
| 시스템 임시격리 | 자동점검 중 | 상태가 자동복구 가능한지 관찰 |
| `SAFE_MODE` | 안전정지 | `/account`·주문상태·원장 확인 |
| 운영자 halt | 대표 긴급정지 | 원인 제거 후 `/resume` 검토 |
| `UNKNOWN` 주문 | 주문결과 확인 필요 | 재주문 금지, 실제 Toss 상태 확인 |
| 부분체결·미완료 SELL | 위험축소 진행 중 | 신규 BUY 금지 |
| 계좌·원장 불일치 | 정합성 확인 필요 | 신규 BUY 금지 |

`UNKNOWN`을 실패로 단정하거나 같은 주문을 자동 재전송하도록 안내하지 않습니다.

## 12. 메시지 표현 표준

모든 실거래 메시지는 가능한 한 다음 우선순위로 읽히게 합니다.

1. **현재 상태** — 정상 / 시작 대기 / 자동점검 / 안전정지 / 운영자 긴급정지
2. **현재 성과** — 자동운용자산 / 누적손익 / 누적수익률
3. **자금 범위** — 기준자금 / 자동운용비율 / 목표·현재 허용원금
4. **오늘 영향** — 신규 자동매수 / 위험축소 / 진행 중 주문
5. **운영자 행동** — 없음 / 확인 필요 / `/halt` / `/account` / `/resume`
6. **상세정보** — 종목·수량·가격·목표비중·내부 상태

정상일 때는 `대표님 행동: 없음`을 명확히 표시합니다.

## 13. 용어 표준

| 표시 | 뜻 |
|---|---|
| 운용 기준자금 | 100% 자동운용 시 기준이 되는 운영자 설정 원금 |
| 자동운용비율 | 기준자금 중 JH AUTO에 위임한 비율 |
| 목표 자동원금 | 기준자금 × 자동운용비율 |
| 현재 허용원금 | 현재 자금개방 단계까지 위험예산에 사용할 수 있는 원금 |
| HWM75 현재 위험예산 | 현재 허용원금과 최고 자동운용 평가액으로 계산한 위험확대 상한 |
| 현재 투자액 | 관리종목 실제 평가액 합계 |
| 대기현금 | JH AUTO 관리 현금 |
| 자금축소 회수대기 | 감액 후 위험축소 SELL이 끝나지 않아 회수되지 않은 내부 금액 |

`자동운용비율 20%`를 `시장 투자비율 20%`라고 표현하지 않습니다. 시장노출은 JDSS가 결정합니다.

## 14. 성과 표시 표준

전체 기본 세트:

```text
자동운용자산      $10,438
누적 운용손익      +$438
누적 운용수익률    +4.38%
```

누적수익률은 외부자금 유입·회수 영향을 제거한 단위가치 기반 성과입니다.

종목별:

```text
QQQ
평가손익     +$139.50
보유수익률     +2.21%
```

평단이 없거나 보유수량이 0이면 수익률을 임의 계산하지 않습니다.

## 15. 메시지 길이와 상세정보

- 첫 화면은 상태·성과·자금·행동을 우선하고 세부 내부상태를 과도하게 노출하지 않습니다.
- Telegram 4,096자 제한을 넘지 않도록 상세 종목정보는 `/portfolio`, 주문 상세는 해당 상세화면으로 분리합니다.
- traceback, secret, 인증 header, 전체 계좌번호, 내부 host 식별자를 Telegram에 노출하지 않습니다.
- 개발자 내부코드값은 필요한 경우 쉬운 운영자 표현 뒤에 보조정보로 표시합니다.

## 16. 메시지 변경 시 개발자 체크리스트

Telegram UI/문구를 바꾸면 최소 다음을 검증합니다.

- 관리자 Chat ID와 private chat 인증
- callback의 `chat.id` / `from_user.id`
- callback token TTL·1회성·stale state·revision 검증
- 4,096자 제한
- `/dashboard`, `/today`, `/auto`, `/portfolio`, `/account`, `/halt`, `/resume`, `/help` 포맷
- 최초 시작 callback 주문 0건
- 설정변경 callback 주문 0건
- `UNKNOWN`을 실패로 오표시하지 않음
- 실제 연구 기준 `$50,000`을 실거래 고정한도로 표시하지 않음
- 운영자 `/halt`를 시스템이 자동해제한다고 표현하지 않음

정확한 자동주문·자금·안전 계약을 Telegram 문서가 새로 만들지 않습니다. 계약 변경이 필요하면 먼저 `JH_AUTO_SPEC.md`와 코드·테스트를 변경한 뒤 이 가이드의 사용자 표현을 동기화합니다.
