# JDSS Telegram Bot 운영 가이드 — 현재판

이 문서는 Telegram에서 JDSS V3.2.2를 실제로 어떻게 확인하고 주문하는지 설명하는 운영 가이드입니다. 전략 수학은 `STRATEGY_GUIDE.md`, 주문·최초진입의 정확한 계약은 `JDSS_FINAL_SPEC.md`, 현재 배포 상태는 `CURRENT_WORK.md`를 따릅니다.

## 1. 가장 중요한 사용법

평소에는 `/dashboard`에서 **`오늘 주문 한번에 검토`**만 누르면 됩니다.

1. 시스템은 오전 7시 이후 완결봉으로 이미 계산된 오늘 목표비중을 사용합니다.
2. 먼저 위험축소 SELL이 남아 있는지 확인합니다.
3. SELL이 남아 있으면 새 BUY를 만들지 않고 `매도 완료 대기`만 보여줍니다.
4. SELL이 끝난 뒤 브로커와 JDSS 원장이 일치하고 SAFE_MODE가 아니어야 BUY 검토가 열립니다.
5. QQQ/TQQQ/SOXL 중 오늘 더 사야 하는 종목을 한 화면에 모아 수량·지정가·예상금액을 보여줍니다.
6. 운영자가 **`오늘 모의매수 N건 전체 실행`** 또는 향후 승인된 live의 **`오늘 실매수 N건 전체 실행`**을 한 번 누르면 각 종목 주문을 순서대로 제출합니다.
7. 최종 버튼을 누르는 순간 각 주문의 가격·수량·현금·허용 세션을 다시 검증합니다.

즉 전략 판단과 주문수량 계산은 자동이고, 위험축소 SELL은 자동이며, 위험을 늘리는 BUY만 사람이 최종 승인하는 반자동 구조입니다.

현재 Oracle은 **forced dry-run**이고 live는 잠겨 있습니다. 따라서 현재의 `전체 실행`은 실제 Toss 매수가 아니라 DRY 모의주문입니다.

## 2. 화면 용어

| 화면 표현 | 뜻 |
|---|---|
| `목표비중` | 전략이 현재 계좌에서 맞추려는 종목별 비율 |
| `현재 보유비중` | JDSS 원장 기준 현재 보유 비율 |
| `보유/목표` | 해당 종목의 목표·현재수량·열린 주문·안전상태 확인 |
| `추가매수 판단` | TQQQ/SOXL 점수로 QQQ 일부를 추가 레버리지로 바꿀지 보는 보조 판단 |
| `오늘 주문 한번에 검토` | 오늘 필요한 BUY를 한 화면에 모아 최종 승인 전까지 검토 |
| `개별 매수 보기` | 특정 BUY 신호를 종목별 2단계 승인으로 처리하는 비상용/상세 경로 |
| `미체결 주문 보기` | 이미 제출됐지만 끝나지 않은 BUY/SELL 확인 |
| `위험한도` | HWM75 규칙으로 현재 전략이 투자에 사용할 수 있는 위험예산 |

`추가매수 판단` 버튼 자체가 주문 버튼은 아닙니다. 최종 목표비중이 실제로 증가해야 `오늘 주문` 또는 `/signal`에 BUY 후보가 생깁니다.

## 3. 대시보드 버튼

`/dashboard`의 기본 운영 순서는 다음과 같습니다.

- **`오늘 주문 한번에 검토`**: 가장 먼저 사용할 기본 버튼입니다.
- `QQQ/TQQQ/SOXL 보유/목표`: 종목별 목표와 현재 상태를 확인합니다.
- `TQQQ/SOXL 추가매수 판단`: 추가 레버리지 점수를 확인합니다.
- `개별 매수 보기`: 오늘 BUY를 종목별로 따로 검토할 때 사용합니다.
- `미체결 주문 보기`: 제출된 주문의 진행 상태를 확인합니다.

명령으로는 `/today`가 `오늘 주문 한번에 검토`와 같은 역할을 합니다.

## 4. 오늘 주문 시나리오

### A. 오늘 아무 주문도 없을 때

`오늘 주문 한번에 검토`를 누르면 `오늘 목표비중에 맞춘 추가 주문이 없습니다`라고 표시합니다. 버튼을 더 누를 필요가 없습니다.

### B. BUY만 필요한 날

예를 들어 오늘 목표상 QQQ 5주, TQQQ 3주가 부족하면 다음처럼 한 번에 표시합니다.

- QQQ 5주 / 지정가 상한 / 예상금액
- TQQQ 3주 / 지정가 상한 / 예상금액
- 총 예상 매수금액
- 실행 전 현금과 예상 잔여 현금

그 아래 **`오늘 모의매수 2건 전체 실행`** 버튼 하나가 표시됩니다. 이 버튼은 짧은 유효시간을 가지며 실행 순간 모든 종목을 다시 검증합니다.

### C. SELL 후 BUY가 필요한 날

목표비중 변경으로 어떤 종목은 줄이고 다른 종목은 늘려야 한다면 시스템은 다음 순서를 강제합니다.

1. 위험축소 SELL 자동 제출
2. SELL 전량 완료 확인
3. JDSS 원장에 체결 반영
4. 브로커/원장 reconciliation 확인
5. 이상이 없을 때만 새 BUY 후보 생성
6. 운영자가 `오늘 주문 한번에 검토` 후 BUY 전체 승인

SELL이 `SUBMITTED`, `PARTIAL_FILLED`, `PENDING_CANCEL`, `UNKNOWN` 등 종료되지 않은 상태라면 `오늘 주문`은 BUY 버튼을 만들지 않습니다.

### D. 이미 BUY 주문이 진행 중일 때

기존 BUY가 미체결이면 새 일괄 BUY를 만들지 않습니다. `미체결 주문 보기`에서 먼저 기존 주문을 확인합니다. 이는 같은 목표수량을 중복 주문하는 것을 막기 위한 장치입니다.

### E. 최종 실행 중 한 종목에서 조건이 바뀔 때

전체 실행은 여러 실제 주문을 하나의 증권사 주문으로 합치는 기능이 아닙니다. QQQ/TQQQ/SOXL 주문을 안전하게 순서대로 제출하는 편의 기능입니다.

예를 들어 QQQ 주문은 제출됐지만 TQQQ에서 가격·수량·현금 조건이 달라지면:

- 이미 제출된 QQQ 주문은 취소하거나 되돌렸다고 가정하지 않습니다.
- TQQQ에서 실행을 중단합니다.
- 그 뒤 남은 SOXL 등의 승인도 자동 취소합니다.
- 운영자에게 `앞에서 이미 제출된 주문은 되돌리지 않습니다`라고 안내합니다.
- `미체결 주문 보기` 확인 후 다시 `오늘 주문 한번에 검토`를 눌러 최신 상태로 계산합니다.

주문 결과가 `UNKNOWN`이면 성공으로 추정해 재주문하지 않고 SAFE_MODE 절차를 따릅니다.

## 5. 최초진입 50% → 75% → 100%

`/onboarding`은 새 계좌가 한 번에 전액 진입하지 않도록 매수 가능한 누적 한도만 단계적으로 엽니다.

| 단계 | 최종 목표 대비 누적 한도 | 다음 단계 조건 |
|---|---:|---|
| 1차 | 50% | 현재 단계 목표수량 전량 체결 후 최소 3 미국 거래일 |
| 2차 | 75% | 현재 단계 목표수량 전량 체결 후 최소 3 미국 거래일 |
| 3차 | 100% | 전량 체결 시 최초진입 완료 |

`1차 매수 한도 열기 · 50%` 같은 단계 버튼은 **주문을 제출하지 않고 한도만 엽니다.** 단계가 열린 뒤 `/dashboard`의 `오늘 주문 한번에 검토`를 누르면 그 단계에서 필요한 QQQ/TQQQ/SOXL BUY를 한 화면에서 검토하고 한 번에 승인할 수 있습니다.

종목별로 따로 확인하고 싶을 때만 `개별 매수 보기` 또는 `/signal`을 사용합니다.

오래된 단계 버튼의 **callback**에는 버튼 생성 당시 단계번호가 들어 있으며, 현재 DB 단계와 다르면 거부합니다. 과거 Telegram 메시지의 오래된 callback을 다시 눌러도 단계가 중복 상승하지 않습니다.

## 6. 개별 매수 경로

기존 종목별 2단계 승인도 그대로 남아 있습니다.

1. `개별 매수 보기` 또는 `/signal`
2. `종목 매수 주문 검토하기`
3. 최신 가격·남은 목표수량·현금·세션 재계산
4. 지정가·수량·예상수수료 확인
5. `종목 N주 모의매수 실행` 또는 향후 승인된 `종목 N주 실매수 실행`
6. 주문번호·상태·체결수량 회신

일괄 주문이 불편하거나 특정 종목만 따로 확인해야 할 때 사용하는 보조 경로입니다.

## 7. 주문 상태 읽기

| 상태 | 뜻 | 운영자 행동 |
|---|---|---|
| `CREATED`·`SUBMITTED`·`PENDING` | 접수됐지만 끝나지 않음 | `미체결 주문 보기`에서 계속 확인 |
| `PARTIAL_FILLED` | 일부 체결 | 남은 수량을 주문 모니터가 감시; 중복 주문 금지 |
| `FILLED` | 전량 체결 | 원장 반영과 정합성 확인 |
| `CANCELED`·`REJECTED`·`REPLACED` | 주문이 정상 전량 체결로 끝난 것이 아님 | 최신 목표와 `/signal`, `/errors` 확인 |
| `UNKNOWN` | 제출 결과를 증명할 수 없음 | 성공으로 추정하거나 재주문하지 말고 SAFE_MODE 확인 |

주문 감시·정합성 점검·안전 경고는 기존 1분 주기를 유지합니다.

| 명령 | 기능 |

| `/dashboard` | 통합 대시보드와 주요 버튼 |

미국 정규장 마감 뒤 일일 목표비중·분석은 서머타임과 무관하게 한국시간 오전 7시 이후 생성합니다. `오늘 주문`은 그 확정된 목표를 사용하며 버튼을 누른다고 임의로 전략 신호를 새로 만들지 않습니다.

## 9. 실거래 잠금

Toss 주문 API 어댑터가 코드에 존재하는 것과 현재 실주문이 허용되어 있다는 것은 별개입니다. 현재 V3.2.2는 forced dry-run이며 live hard lock을 유지합니다.

향후 live 전환 시에도 이 가이드의 UX 원칙은 같습니다.

- 위험축소 SELL 우선
- SELL 완료와 reconciliation 전 BUY 차단
- BUY는 `오늘 주문 한번에 검토` 후 최종 사람 승인
- 최종 실행 순간 가격·수량·현금·세션 재검증
- 실패 시 이미 제출된 주문을 임의로 되돌리지 않고 남은 주문만 중단
- UNKNOWN 또는 정합성 실패 시 SAFE_MODE

live 전환은 Telegram 버튼만으로 활성화할 수 없으며 별도의 구현 검증과 명시적 활성화 승인이 필요합니다.
