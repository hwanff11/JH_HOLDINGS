# JH_HOLDINGS Telegram 운영 가이드

이 문서는 운영자가 Telegram에서 **자동운용 상태를 확인하고, 기준자금·자동운용비율·최초 시작·긴급정지를 통제하는 방법**을 설명합니다.

- 투자전략: [`JDSS_FINAL_SPEC.md`](JDSS_FINAL_SPEC.md)
- 자동매매 계약: [`JH_AUTO_SPEC.md`](JH_AUTO_SPEC.md)
- 실거래 메시지 표현: [`TELEGRAM_LIVE_MESSAGE_STANDARD.md`](TELEGRAM_LIVE_MESSAGE_STANDARD.md)
- 현재 실제 운영 상태: [`../CURRENT_WORK.md`](../CURRENT_WORK.md)

JH AUTO 1.0.0부터 Telegram의 기본 역할은 **매수 승인기**가 아니라 **자동운용 통제·감시 화면**입니다.

---

## 1. 평소에는 세 화면만 보면 됩니다

```text
/dashboard   전체 상태·전체 수익률
/today       오늘 종목별 목표·보유수익률·자동주문 상황
/auto        기준자금·자동운용비율·최초 시작·자금투입 단계
```

실제 Toss 계좌를 직접 확인하고 싶을 때 `/account`, 종목별 상세는 `/portfolio`를 봅니다.

정상 자동운전 중 운영자의 기본 행동은 **없음**입니다.

---

## 2. 첫 화면 메뉴

| 메뉴 | 용도 |
|---|---|
| `/dashboard` | 자동운용 전체 상태와 전체 수익률 |
| `/today` | 오늘 자동매매 예정/진행, 종목별 보유수익률 |
| `/auto` | 운용 기준자금, 자동운용비율, 최초 시작 |
| `/account` | 실제 Toss 계좌·보유·매수가능금액 확인 |
| `/portfolio` | QQQ/TQQQ/SOXL 종목별 보유·목표·수익률 |
| `/backtest` | JDSS 3.2.2 과거검증 |
| `/halt` | 대표 긴급 신규매수 정지 |
| `/help` | 상세 명령과 문제 대응 |

기존 `/onboarding`, `/signal`, 수동 매수승인 기능은 코드 호환·비상점검을 위해 일부 남아 있을 수 있지만 **JH AUTO 정상운영 메뉴에서는 사용하지 않습니다.** 자금투입 50→75→100 단계는 `/auto`가 소유합니다.

---

## 3. `/dashboard`: 가장 먼저 보는 화면

대시보드는 다음 순서로 읽습니다.

1. 현재 자동운용 상태
2. JDSS 전략버전 / JH AUTO 버전
3. 기준자금·자동운용비율·목표 자동원금·현재 허용원금
4. 현재 자동운용자산·누적손익·누적수익률
5. 투자중/현금/HWM75 현재 위험예산
6. 최초 시작승인·대표 긴급정지·시스템 임시격리
7. 진행 중 주문

예시:

```text
[JH_HOLDINGS 자동운용 대시보드]

현재 상태          자동운전 정상
투자전략           JDSS 3.2.2
자동매매           JH AUTO 1.0.0

운용 기준자금      $50,000
자동운용비율       20%
목표 자동원금      $10,000
현재 허용원금      $10,000

자동운용자산       $10,438
누적 운용손익      +$438
누적 운용수익률    +4.38%
HWM75 현재 위험예산 $10,438
```

여기서 `$50,000`은 **표시 예시**입니다. JDSS의 공식 연구·백테스트 기준도 `$50,000`이지만 실제 운용 기준자금은 대표가 정하며 최초 시작 이후에도 변경할 수 있습니다.

최초 시작 전에는 과거 V3.2.2 원장에 HWM `$50,000`이 남아 있더라도 다음처럼 표시합니다.

```text
최고 평가액           시작 전
HWM75 현재 위험예산   시작 전
```

### 전체 수익률 의미

전체 누적수익률은 기준자금이나 자동운용비율을 중간에 바꿔도 자금 유입·회수를 수익으로 오해하지 않도록 **단위가치 기반 시간가중 성과**로 표시합니다.

따라서 `$10,000 → $25,000`으로 자동운용 원금을 늘렸다고 수익률이 갑자기 +150%가 되지 않습니다.

## 4. `/portfolio`: 종목별 보유·수익률

포트폴리오 화면에는 전체 성과와 종목별 현재 보유 성과를 함께 표시합니다.

예시:

```text
전체
자동운용자산      $10,438
누적 운용손익      +$438
누적 운용수익률    +4.38%
현재 허용원금      $10,000
HWM75 현재 위험예산 $10,438

QQQ
보유               9주
목표              10주
평균단가          $700.00
현재가            $715.50
평가손익          +$139.50
보유수익률          +2.21%

TQQQ
...
```

### 종목별 보유수익률 의미

`보유수익률 = 현재 보유분 평가손익 / 현재 보유분 원가`

과거에 매도해 확정한 손익과 현재 보유분 성과를 섞지 않습니다.

종목별 수익률을 서로 더해서 전체 수익률로 사용하지 않습니다.

---

## 5. `/today`: 승인화면이 아니라 오늘 자동운용 관찰화면

JH AUTO에서 `/today`는 사람이 BUY를 누르는 화면이 아닙니다.

표시 항목:

- 전체 누적수익률·누적손익
- 현재 미국장 상태
- QQQ/TQQQ/SOXL 보유수익률
- 현재수량 → 목표수량
- 필요한 자동매수 또는 위험축소 수량
- 자동 BUY가 차단돼 있다면 이유

예시:

```text
[오늘 자동운용]

전체 누적수익률  +4.38%
전체 누적손익    +$438

QQQ   9 → 10주   보유수익률 +2.21%   +1주 자동매수 필요
TQQQ  목표 충족   보유수익률 +4.92%
SOXL  3 → 2주    보유수익률 -1.35%   1주 위험축소 필요

대표님이 별도로 개별 BUY를 승인할 작업은 없습니다.
```

JH AUTO 1.0.0 신규 자동 BUY는 **미국 정규장**에서만 실행합니다.

---

## 6. `/auto`: 자동운용 통제센터

`/auto`에서 확인하는 값:

- 운용 기준자금
- 자동운용비율
- 목표 자동원금
- 현재 허용원금
- 현재 자금투입 단계
- 최초 시작승인 여부
- HWM75 현재 위험예산의 기준 설명
- 최근 자동주문

### 직접 입력

```text
/auto capital 50000
/auto ratio 20
/auto start
```

`50000`은 예시입니다. 허용범위 안에서 대표가 원하는 운용 기준자금을 직접 정할 수 있습니다.

자주 쓰는 기준자금·비율은 화면 버튼으로도 제공합니다.

모든 변경은 **2단계 확인**입니다. 첫 명령/버튼은 검토화면만 만들고, 두 번째 확정버튼에서 실제 운영설정이 바뀝니다.

확인버튼은 일회성이며 일정 시간이 지나거나 서버가 재시작되면 다시 검토해야 합니다.

---

## 7. 운용 기준자금 변경

예:

```text
현재 기준자금      $50,000
변경 기준자금      $70,000
현재 자동운용비율  20%

목표 자동원금
$10,000 → $14,000
```

대표가 확정해야 적용됩니다.

기준자금 증가는 시스템이 스스로 할 수 없습니다.

이미 자동운용이 시작된 뒤 증가분이 생기면 **추가된 원금만** 50→75→100% 단계로 엽니다. 외부자금 증가는 투자수익으로 계산하지 않습니다.

---

## 8. 자동운용비율 변경

예:

```text
/auto ratio 20
```

버튼 기본값:

```text
10% / 20% / 30%
50% / 75% / 100%
```

1~100% 범위의 값을 직접 입력할 수 있습니다.

### 비율을 올릴 때

위험이 증가하므로 추가 원금만 50→75→100% 단계로 엽니다.

### 비율을 내릴 때

위험감소이므로 단계진행을 기다리지 않고 새 허용원금으로 낮춥니다. 필요한 보유량 감소는 JDSS 목표 재계산 후 자동 위험축소 매도로 처리합니다.

### 0%는 사용하지 않습니다

`0%`는 “매수만 잠시 멈춤”인지 “전체 자동운용 자금 회수”인지 모호합니다.

신규 BUY만 멈추려면 `/halt`를 사용합니다.

---

## 9. 최초 자동운용 시작

이 단계가 가장 중요합니다.

**JH AUTO가 배포돼도 실제 BUY는 시작되지 않습니다.**

먼저:

1. `/auto`에서 기준자금 설정
2. `/auto`에서 자동운용비율 설정
3. `/auto start` 또는 `최초 자동운용 시작 검토`
4. 최종 확인버튼

을 거칩니다.

최종 확인버튼을 눌러도 **그 버튼 처리 중 Toss 주문은 0건**이어야 합니다.

버튼은 최초 시작승인과 1단계 허용원금만 기록합니다.

첫 실제 BUY는 다음 독립 안전주기에서:

```text
계좌·원장 일치
→ 미체결 없음
→ 안전정지 없음
→ 대표 긴급정지 없음
→ 미국 정규장
→ 최신 목표·가격·수량 재계산
→ OrderManager 최종검증
```

을 모두 통과한 뒤에만 가능합니다.

## 10. 첫 자금투입 50→75→100

목표 자동원금 $10,000을 예로 들면:

| 단계 | 현재 허용원금 |
|---|---:|
| 1단계 | $5,000 |
| 2단계 | $7,500 |
| 3단계 | $10,000 |

단순히 3일이 지나면 올라가는 것이 아닙니다.

현재 단계의 **실제 JH AUTO 체결 최소 1건 + JDSS 목표수량 충족 + 미체결 0 + 계좌대조 정상 + SAFE_MODE 없음 + 최소 3 미국 거래세션** 조건이 필요합니다.

정수주 반올림으로 거래할 수량이 우연히 0이라는 이유만으로 다음 단계로 승격하지 않습니다.

정상이라면 대표가 2단계·3단계를 다시 눌러줄 필요가 없습니다.

---

## 11. 자동주문은 한 번에 하나씩

JH AUTO는 한 안전주기에서 신규 BUY를 최대 1건만 실행합니다.

```text
QQQ 주문
→ 주문감시
→ 체결상태 확인
→ 계좌·원장 대조
→ 다음 안전주기
→ TQQQ 주문 가능
```

여러 종목을 동시에 제출하지 않습니다.

부분체결이나 거부가 발생했다고 잔여수량을 즉시 반복주문하지 않습니다. 최신 목표와 실제 보유수량을 다음 정상주기에서 다시 계산합니다.

---

## 12. 주문 상태를 보는 법

| 표시 | 의미 | 처리 |
|---|---|---|
| 실주문 접수 | 주문 접수, 아직 전량체결 아님 | 주문감시 |
| 실주문 부분체결 | 일부 체결 | 자동 잔량 재주문 금지 |
| 실주문 체결 완료 | 전량체결 확인 | 원장반영 후 계좌대조 |
| 실주문 거부 | 주문 미체결/거부 | 최신 조건 재계산 |
| 실주문 취소 확인 | 원주문 취소 확인 | 다음 주기 재계산 |
| 실주문 결과 확인 필요 | 성공·실패 확정 불가 | **재주문 금지, 안전정지 우선** |

`UNKNOWN`을 단순 실패라고 가정해 다시 주문하지 않습니다.

---

## 13. `/halt`: 대표 긴급정지

대표가 이상하다고 판단하면 가장 먼저:

```text
/halt
```

를 실행합니다.

동작:

- 신규 BUY 즉시 차단
- 활성 BUY 승인 취소
- 미체결 BUY 취소 시도
- 취소 요청만으로 취소 완료라 판단하지 않음
- 위험축소 SELL·주문감시·계좌대조는 가능한 범위에서 계속

JH AUTO에서 대표 `/halt`는 **지속되는 운영자 정지표시**를 남깁니다. 시스템이 스스로 풀 수 없습니다.

해제는 `/resume`의 기존 2단계 안전확인과 계좌·원장 재대조를 통과해야 합니다.

---

## 14. 시스템 임시격리와 대표 긴급정지의 차이

### 시스템 임시격리

서버 재시작 또는 자동운용 내부 이상 시 시스템이 신규 BUY를 잠깐 막는 상태입니다.

이미 최초 시작승인이 있고 계좌·원장·주문상태가 모두 정상임을 증명하면 자동복귀할 수 있습니다.

### 대표 긴급정지

대표가 `/halt`로 건 정지입니다.

시스템 자동복귀 금지입니다.

---

## 15. `/account`

실제 Toss 계좌를 조회합니다.

- USD 주문가능금액
- 보유 미국주식
- 실제 수량
- 평균단가
- 현재가
- Toss가 제공하는 평가손익

JH AUTO 성과와 실제 Toss 전체계좌 성과는 범위가 다를 수 있습니다. 같은 계좌의 비관리 종목은 JH AUTO 성과에 포함하지 않습니다.

## 17. 문제가 생겼을 때

일반 대응순서:

```text
/halt
→ /order
→ /account
→ /errors
→ 실제 주문/보유 확인
→ 계좌·원장 일치 증명
→ 필요할 때 /resume
```

하지 말아야 할 것:

- 주문 성공/실패를 추측
- UNKNOWN을 실패로 보고 같은 주문 다시 보내기
- SAFE_MODE 강제삭제
- 실제 계좌와 원장이 다른데 자동운용 재개

## 18. 첫 배포 후 기대 화면

JH AUTO 1.0.0을 운영 서버에 처음 설치한 직후에는 다음이 정상입니다.

```text
자동매매 설치          완료
최초 시작승인          미승인
시스템 임시격리        ON
현재 허용원금          $0
최고 평가액            시작 전
HWM75 현재 위험예산    시작 전
실제 신규 BUY          차단
```

이 상태에서는 코드·Telegram·계좌조회가 정상이어도 실제 매수는 나가지 않습니다.

대표가 직접 자금설정과 최초 시작승인을 마친 뒤에만 자동운용이 시작될 수 있습니다.
