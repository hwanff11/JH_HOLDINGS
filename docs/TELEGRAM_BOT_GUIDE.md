# JDSS 텔레그램 운영 가이드

이 문서는 **운영자가 텔레그램에서 무엇을 확인하고 어떤 버튼을 눌러야 하는지**만 설명합니다. 어려운 내부 용어는 꼭 필요한 경우에만 한글 설명 뒤에 괄호로 표시합니다.

전략 자체는 [`STRATEGY_GUIDE.md`](STRATEGY_GUIDE.md), 정확한 주문 규칙은 [`JDSS_FINAL_SPEC.md`](JDSS_FINAL_SPEC.md), 현재 실거래 상태는 [`../CURRENT_WORK.md`](../CURRENT_WORK.md)를 따릅니다. 실거래 메시지의 표현 기준은 [`TELEGRAM_LIVE_MESSAGE_STANDARD.md`](TELEGRAM_LIVE_MESSAGE_STANDARD.md)를 따릅니다.

## 1. 결론: 평소에는 세 화면만 보면 됩니다

```text
/dashboard  오늘 상태와 해야 할 일 확인
    ↓
/today      오늘 주문이 있으면 수량·가격 검토
    ↓
/account    실제 토스 계좌와 체결 결과 확인
```

첫 투자 기간에는 `/onboarding`에서 50% → 75% → 100% 단계만 추가로 확인합니다.

시스템은 시장·목표비중·주문수량 계산, 위험축소 매도, 계좌 대조와 체결 감시를 담당합니다. 운영자는 **위험을 늘리는 매수의 수량·가격 확인과 최종 승인**만 담당합니다.

## 2. 첫 화면 메뉴는 8개입니다

| 메뉴 | 언제 사용하나요? |
|---|---|
| `/dashboard` | 매일 가장 먼저 확인 |
| `/today` | 오늘 주문과 해야 할 행동 확인 |
| `/account` | 실제 토스 잔고·보유·미체결 확인 |
| `/portfolio` | 목표비중·종목상세·점수 확인 |
| `/backtest` | 과거검증 결과 확인 |
| `/onboarding` | 첫 투자 50% → 75% → 100% 단계 확인 |
| `/halt` | 이상 징후가 있을 때 신규 매수를 즉시 중지 |
| `/help` | 전체 기능과 문제 대응 방법 확인 |

기존 상세 명령은 삭제하지 않았습니다. 평소 메뉴에서만 숨겼으며 `/help`에서 확인할 수 있습니다.

`/resume`은 실계좌의 신규 매수 잠금을 푸는 기능이므로 첫 화면에 표시하지 않습니다. 안전점검이 끝난 뒤에만 사용합니다.

## 3. `/dashboard`: 오늘 상태와 해야 할 일

대시보드에서는 다음 순서로 확인합니다.

1. 실계좌 연결 여부
2. 신규 매수 잠금 여부
3. 계좌 대조 결과
4. 총자산·현금·투자한도
5. QQQ·TQQQ·SOXL 목표와 현재 보유
6. 매수 승인 대기 건수

버튼도 아래 다섯 개만 표시합니다.

- 오늘 주문 확인
- 실제 계좌
- 첫 투자 단계
- 목표·보유 상세
- 진행 중 주문

목표비중·종목상세·점수와 과거검증은 첫 화면 메뉴에서도 바로 열 수 있습니다.

## 4. `/today`: 실제 주문 여부의 최종 판단

주문 가능시간은 미국 **장전·정규장·장후**입니다. 현재가 응답 시각이 없거나 5분보다 오래되면 승인 생성·실행을 중단하고 최신 가격을 다시 확인합니다.

아침 알림에 “지금 승인할 매수가 없습니다”라고 적혀 있어도 실제 주문 여부는 `/today`에서 최종 확인합니다. 주문 가능시간, 미체결 상태와 계좌 상황이 바뀔 수 있기 때문입니다.

`/today`는 다음을 자동으로 확인합니다.

1. 주문 가능한 시간인지
2. 최신 미국 거래일 계산이 끝났는지
3. 목표수량이 확정됐는지
4. 먼저 끝내야 할 매도가 없는지
5. 기존 매수 주문이 남아 있지 않은지
6. 실제 계좌와 JDSS 기록이 일치하는지
7. 안전정지 상태가 아닌지
8. JDSS 투자한도와 토스 매수가능금액이 충분한지

확인되지 않는 항목이 하나라도 있으면 신규 매수를 열지 않습니다. 이것을 내부적으로는 “확인 불가 시 차단(fail-closed)”이라고 부릅니다.

## 5. 오늘 매수가 있는 경우

화면에서 종목별 정수주 수량·지정가·예상금액, 전체 예상금액, JDSS 현금·투자한도와 계좌 대조 결과를 확인합니다.

그다음 `오늘 실매수 N건 순차 실행` 버튼을 누릅니다. 실제 제출 직전에 가격·수량·계좌 상태를 다시 확인합니다. 값이 달라졌다면 과거 화면으로 주문하지 않고 새 검토를 요구합니다.

여러 종목 주문은 하나의 주문이 아니라 **종목별 순차 주문**입니다. 앞 주문이 제출된 뒤 조건이 달라지면 나머지 주문은 중단될 수 있습니다. 이미 제출한 주문을 자동 반대매매로 되돌리지는 않습니다.

### 실주문을 보낸 뒤 표시되는 상태

| 텔레그램 표시 | 의미 | 운영자 행동 |
|---|---|---|
| 실주문 접수 | 토스가 주문을 접수했지만 체결 완료 전 | `/order`에서 진행 확인 |
| 실주문 부분체결 | 일부 수량만 체결 | 재주문하지 말고 남은 수량 감시 |
| 실주문 체결 완료 | 전체 수량 체결 확인 | `/account`에서 실제 보유 확인 |
| 실주문 거부 | 주문이 거부됨 | 원인 확인 후 유효시간 내 재승인 검토 |
| 실주문 취소 확인 | 주문 취소 상태 확인 | 필요하면 새 검토부터 다시 시작 |
| 실주문 변경 확인 필요 | 주문 상태가 변경됨 | `/order`에서 원주문 상태 우선 확인 |
| 실주문 결과 확인 필요 | 성공·실패를 확정할 수 없음 | **재주문 금지**, `/order`·`/account` 대조 후 안전정지 해제 검토 |

특히 `UNKNOWN` 계열은 실패로 간주해 같은 주문을 다시 보내는 상태가 아닙니다. 중복매수 위험이 있으므로 **실제 계좌에서 결과를 확인하기 전에는 재주문하지 않습니다.**

## 6. 매도 후 매수가 필요한 경우

위험을 줄이는 매도는 항상 먼저 처리합니다.

```text
위험축소 매도
  → 체결 확인
  → JDSS 기록 반영
  → 실제 계좌와 대조
  → 이상 없음
  → 신규 매수 검토 가능
```

매도가 진행 중이거나 결과를 확정할 수 없으면 신규 매수를 승인하지 않습니다.

## 7. 첫 투자 50% → 75% → 100%

`/onboarding`은 주문 버튼이 아니라 **현재 단계의 매수 한도를 여는 기능**입니다.

| 단계 | 최종 목표 대비 누적 한도 | 다음 단계 조건 |
|---|---:|---|
| 1차 | 50% | 현재 단계 체결 완료 후 최소 3 미국 거래일 |
| 2차 | 75% | 현재 단계 체결 완료 후 최소 3 미국 거래일 |
| 3차 | 100% | 체결 완료 후 일반운용 전환 |

단계 버튼을 눌러도 주문이 즉시 전송되지 않습니다. 이후 `/today`에서 수량과 가격을 다시 보고 최종 승인합니다.

## 8. 문제가 생겼을 때

다음 순서만 지키면 됩니다.

1. `/halt`로 신규 매수 중지
2. `/order`에서 진행 중 주문 확인
3. `/account`에서 실제 토스 상태 확인
4. `/errors`에서 최근 문제 확인
5. 주문 성공을 추정하거나 같은 주문을 다시 보내지 않기
6. 계좌와 JDSS 기록의 일치가 확인된 뒤에만 `/resume` 검토

`/halt` 이후에도 이미 제출된 주문은 체결될 수 있습니다. 취소 요청을 보냈다는 사실만으로 취소 완료로 보지 않으며, 토스의 원주문 상태가 취소로 확인되어야 합니다.

## 9. 화면에서 자주 보는 상태

| 표시 | 쉬운 뜻 | 운영자 행동 |
|---|---|---|
| 주문 가능시간 대기 | 지금은 주문할 시간이 아님 | 기다린 뒤 `/today` 재확인 |
| 전략 계산 확인 필요 | 최신 계산이 끝나지 않음 | 주문 없음으로 해석하지 않음 |
| 다음 미국 거래일 대기 | 목표는 나왔지만 주문 시점 전 | 기다림 |
| 위험축소 준비·진행 | 매도를 먼저 처리 중 | 신규 매수 금지 |
| 기존 매수 진행 중 | 미체결 매수가 있음 | `/order` 확인 |
| 계좌·원장 불일치 | 실제 계좌와 JDSS 기록이 다름 | `/halt`, 재주문 금지 |
| 안전정지(SAFE_MODE) | 결과를 확정할 때까지 보호 상태 | 원인 확인 전 매수 금지 |
| 오늘 주문 없음 | 계산·목표·계좌 대조까지 정상 | 아무 행동도 필요 없음 |

## 10. 상세 명령

| 명령 | 기능 |
|---|---|
| `/portfolio` | 목표비중·현재 보유·투자한도 |
| `/status` | 종목별 목표와 보유 상세 |
| `/score` | TQQQ·SOXL 추가매수 판단 |
| `/history` | 최근 추가매수 판단 변화 |
| `/signal` | 개별 매수 승인 경로(비상·상세용) |
| `/order` | 진행 중 주문 |
| `/errors` | 최근 문제와 안전 기록 |
| `/ping` | 봇 작동 상태 |
| `/guide` | 전략 쉬운 설명 |
| `/backtest` 또는 `/bt` | 과거검증 결과 |
| `/resume` | 안전점검 후 신규 매수 재개 |

## 11. 한글 표현 기준

| 내부 용어 | 운영자 화면에서 쓰는 말 |
|---|---|
| BUY / SELL | 매수 / 매도 |
| LIVE-ARMED | 실계좌 연결·매수 잠금 |
| dry-run | 모의운용 |
| SAFE_MODE | 안전정지 |
| reconciliation | 계좌·원장 대조 |
| preflight | 사전점검 |
| batch | 오늘 주문 묶음 |
| onboarding | 첫 투자 단계 |
| broker | 증권사 또는 토스 |
| HWM75 | 최고자산가치 75% 반영 투자한도 |

코드·데이터베이스 식별자는 안정성을 위해 영문을 유지할 수 있지만, 운영자 메시지에는 한글 설명을 먼저 표시합니다.
