# JH AUTO 1.0.0 실거래 전 안전강화 기준

이 문서는 [`JH_AUTO_SPEC.md`](JH_AUTO_SPEC.md)의 실거래 안전계약을 보완합니다. 투자전략 숫자는 바꾸지 않으며 `JDSS 3.2.2`와 `JH AUTO 1.0.0`의 책임을 더 명확하게 분리합니다.

## 1. 자금의 의미

`strategy.yaml`의 `$50,000`은 JDSS 3.2.2 공식 백테스트·회귀검증의 **연구 기준 예시자금**입니다. 실제 실거래 원금이 아닙니다.

실제 운용에서는 운영자가 Telegram에서 다음을 정합니다.

```text
총 투자금액 × 자동운용비율 = 목표 자동원금
```

예:

```text
총 투자금액      $50,000
자동운용비율          20%
목표 자동원금     $10,000
```

LIVE에서 JH AUTO 상태가 누락·손상되면 연구 기준 `$50,000`으로 되돌아가 주문하지 않습니다. 신규 BUY를 차단하고 원인을 확인합니다.

## 2. 최종 BUY 독립 안전검사

상위 전략·자동화 계산이 잘못되어도 마지막 `OrderManager` 경계가 다음 값을 독립적으로 다시 확인합니다.

- JH AUTO 실행계층 활성상태와 버전
- 최초 시작승인 `ON`
- 시스템 임시격리 `OFF`
- 대표 긴급정지 latch `OFF`
- 상태 `RUNNING`
- 총 투자금액의 정상 범위
- 자동운용비율 1~100%
- `목표 자동원금 = 총 투자금액 × 자동운용비율`
- `0 < 현재 허용원금 <= 목표 자동원금`
- HWM이 현재 허용원금 이상
- HWM75 위험예산이 독립 재계산 상한 이하
- 기존 BUY halt와 SAFE_MODE 정상
- 미체결 예약과 브로커 매수가능금액 한도
- 실제 브로커 POST 직전의 미국 정규장 여부

하나라도 증명되지 않으면 BUY는 실패폐쇄(fail-closed)합니다.

## 3. 실제 현재시각 사용

자동주기 시작시각이 정규장이었다는 이유만으로 주문하지 않습니다. 브로커에 상태변경 POST를 보내기 직전 실제 `datetime.now(UTC)` 기준으로 미국 정규장을 다시 확인합니다.

따라서 장 마감 직전 검토가 지연되어 실제 제출시점이 정규장을 벗어나면 신규 AUTO BUY를 제출하지 않습니다.

## 4. 자금설정 변경 중 보호

최초 자동운용을 이미 승인한 뒤 총 투자금액이나 자동운용비율을 바꾸면, 첫 설정 write 전에 기존 BUY 경계를 잠급니다.

```text
BUY halt ON
→ AUTO CONFIGURING/격리
→ 자금·HWM·목표 재계산
→ 계약 일관성 검사
→ 격리 유지
→ 다음 독립 안전주기에서 계좌·원장 재대조
→ 정상 증명 시에만 자동복귀
```

설정 callback 자체가 BUY를 다시 열지 않습니다. 중간 예외가 발생해도 격리상태를 유지합니다.

## 5. 파일럿 단계 승격

최초 파일럿은 50→75→100% 단계로 열립니다. 정수주 반올림 때문에 모든 목표가 0주가 되는 소액구간에서는 `현재수량 >= 목표수량`만으로 단계를 올리지 않습니다.

초기 1단계에서 최소 한 번의 실제 JH AUTO 주문 체결 기록이 있어야 다음 단계 승격을 검토합니다. 시장전략이 거래를 요구하지 않는다면 억지 주문을 만들지 않고 해당 단계에 머뭅니다.

## 6. 주문시도 회로차단기

JH AUTO 1.0.0 파일럿은 반복 오류가 주문요청 폭주로 이어지지 않도록 다음 상한을 둡니다.

- 동일 신호 자동시도 최대 3회/UTC 일자
- 전체 자동 BUY 시도 최대 5회/UTC 일자
- 전체 상한 도달 시 신규 BUY 격리

주문 결과가 `UNKNOWN`이면 이 상한과 별개로 즉시 격리하며 같은 주문을 자동 재전송하지 않습니다.

## 7. 배포 권한과 배포 전 검사

Oracle LIVE-ARMED workflow는 수동실행과 ChatOps issue 모두 repository owner만 실제 deploy job을 실행할 수 있습니다.

실거래 배포 직전에는 기존 live 안전테스트 외에 다음을 다시 실행합니다.

- `tests/test_jh_auto.py`
- `tests/test_jh_auto_prelive_hardening.py`
- `tests/test_live_entrypoints.py`

배포 성공은 자동매매 시작승인이 아닙니다.

## 8. 배포 후 절대 상태

이번 안전강화 배포 뒤에도 다음 계약을 유지합니다.

```text
Oracle 배포                가능
실계좌 조회                가능
Telegram                   가능
대표 최초 AUTO 시작승인    미승인
신규 BUY halt              ON
실제 신규 AUTO BUY         0건
```

운영자가 Telegram의 최초 자동운용 시작을 명시적으로 2단계 승인하기 전에는 실제 신규 BUY가 발생하면 안 됩니다. 배포 과정은 `/resume`이나 `/auto start`를 대신 수행하지 않습니다.
