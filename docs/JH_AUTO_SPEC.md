# JH AUTO 1.0.0 공식 자동운용 사양

이 문서는 **자동매매 실행·자금·성과·최초 시작·정지·안전계약의 단일 기준(SSOT)** 입니다.

투자판단 자체는 [`JDSS_FINAL_SPEC.md`](JDSS_FINAL_SPEC.md)의 JDSS 3.2.2가 소유합니다. JH AUTO는 전략을 바꾸지 않고, JDSS가 만든 목표를 실제 계좌에서 얼마만큼·어떤 안전조건으로 실행할지를 관리합니다.

## 1. 버전체계와 책임

| 구분 | 현재 버전 | 책임 |
|---|---|---|
| 투자전략 | `JDSS 3.2.2` | 시장판단, 목표노출, QQQ/TQQQ/SOXL 목표비중, RS6M, HWM75 전략 공식 |
| 자동매매 실행계층 | `JH AUTO 1.0.0` | 운용자금, 자동운용비율, 성과회계, 자동승인·주문, 최초 시작, 정지·복구 |

자동매매 코드 변경만으로 JDSS 버전을 올리지 않습니다. 전략 수학 변경만으로 JH AUTO 버전을 올리지 않습니다.

## 2. 자금 정의

### 2.1 운용 기준자금

운영자가 Telegram에서 정하는 실거래 기준 원금입니다. `strategy.yaml`의 `$50,000` 연구 기준과 다른 **운영설정**입니다.

### 2.2 자동운용비율

운용 기준자금 중 JH AUTO에 위임할 비율입니다. 허용범위는 1~100%이며 시스템이 스스로 높일 수 없습니다.

### 2.3 목표 자동원금

```text
목표 자동원금 = 운용 기준자금 × 자동운용비율
```

이 값은 항상 전액을 시장에 투자한다는 뜻이 아닙니다. 실제 시장투자 목표는 JDSS 목표노출에 따라 작아질 수 있습니다.

### 2.4 현재 허용원금

목표 자동원금 중 현재 자금개방 단계까지 실제 위험예산 계산에 사용할 수 있도록 열린 원금입니다.

```text
0 <= 현재 허용원금 <= 목표 자동원금
```

최초 시작승인 전에는 현재 허용원금이 0이어야 합니다.

## 3. 최초 자금개방과 증액·감액

새 위험은 한 번에 열지 않습니다.

### 3.1 최초 시작

```text
1단계 50%
2단계 75%
3단계 100%
```

각 단계 승격에는 모두 다음이 필요합니다.

1. 현재 단계의 JDSS 목표수량 충족
2. 미체결 주문 0
3. 실계좌와 원장 대조 정상
4. SAFE_MODE·대표 긴급정지·시스템 임시격리 없음
5. 현재 단계 충족 후 최소 3 미국 거래세션 경과
6. **해당 단계에서 최소 1건 실제 JH AUTO 주문 체결 증거**

정수주 반올림으로 목표수량이 0주이거나 시간이 지났다는 이유만으로 다음 단계로 자동 승격하지 않습니다. 시장전략이 주문을 요구하지 않으면 억지 주문을 만들지 않고 해당 단계에 머뭅니다.

### 3.2 증액

목표 자동원금이 증가하면 **증가분만** 50→75→100 단계로 엽니다. 기존에 이미 열린 원금을 다시 축소하지 않습니다.

### 3.3 감액

목표 자동원금이 감소하면 단계대기 없이 새 허용원금에 반영하고 위험축소 SELL을 우선합니다. 위험감소는 지연하지 않고 위험증가만 단계적으로 진행합니다.

## 4. JDSS와 JH AUTO의 계산 경계

JDSS가 소유하는 것:

- QQQ 기반 추세·변동성 판단
- 0.5 / 1.0 / 1.25 / 1.5배 목표노출
- SOXX RS6M
- QQQ/TQQQ/SOXL 목표비중
- 최대 5% 추가 레버리지 판단
- HWM 이익 재투자율 75%
- 완결봉 → 다음 거래일 실행 원칙

JH AUTO가 소유하는 것:

- 운용 기준자금·자동운용비율·목표 자동원금·현재 허용원금
- 자금 증액·감액 회계
- 실거래 HWM 재기준화와 성과단위
- 실제 목표수량 계산에 적용할 위험예산
- 자동검토·자동승인·주문 순서
- 최초 시작승인
- 대표 긴급정지·시스템 임시격리·SAFE_MODE
- 운영성과와 Telegram 표시

JH AUTO는 JDSS 목표비중을 임의로 바꾸지 않습니다.

## 5. HWM75와 자금변경 회계

실거래 JH AUTO의 HWM75는 현재 허용원금과 실제 자동운용자산을 기준으로 계산합니다.

```text
위험예산 = min(
  현재 자동운용 평가액,
  현재 허용원금 + 0.75 × max(0, 최고 자동운용 평가액 - 현재 허용원금)
)
```

최초 JH AUTO launch에서는 과거 JDSS 연구·모의원장에 남아 있을 수 있는 `$50,000` HWM/risk state를 실거래 HWM으로 이어받지 않습니다. 최초 사전점검이 성공한 뒤 **1단계 현재 허용원금**에서 새 실거래 HWM을 시작합니다.

운용 기준자금·자동운용비율 변경으로 들어오거나 빠지는 금액은 투자수익으로 계산하지 않습니다.

## 6. 공식 성과회계

포트폴리오 전체 수익률은 외부자금 유입·회수를 제거하기 위해 **단위가치 기반 시간가중 방식**을 사용합니다.

```text
누적수익률 = 현재 단위가치 / 시작 단위가치 - 1
```

Telegram에는 다음을 구분해 표시합니다.

- 현재 자동운용자산
- 누적 운용손익
- 누적 운용수익률
- 현재 허용원금
- HWM75 현재 위험예산

종목별 `보유수익률`은 현재 보유분의 평가손익 / 현재 보유분 원가이며, 종목별 수익률을 더해 포트폴리오 수익률로 사용하지 않습니다.

### 자금축소 회수대기

자동운용 원금을 줄였지만 기존 포지션의 위험축소 매도가 끝나지 않았다면 내부 자동운용 현금은 일시적으로 음수의 **회수대기 부채**가 될 수 있습니다. 이는 Toss 실제 계좌의 마이너스 현금을 뜻하지 않습니다.

성과 평가액은 `회수대기 부채 + 관리 포지션 평가액`으로 계산해 원금 축소를 투자수익으로 오인하지 않습니다. 회수대기 상태에서는 새 위험증가 BUY를 열지 않습니다.

## 7. 최초 시작승인

코드 배포와 최초 자동운용 시작은 별개입니다.

최초 JH AUTO 배포 기본상태:

```text
JH AUTO 설치          완료 가능
계좌·시장 조회         가능
Telegram 설정          가능
최초 시작승인          OFF
현재 허용원금          0
startup quarantine    ON
신규 BUY              차단
```

`/auto start`는 2단계 확인을 사용합니다. 최종 callback은 `launch_authorized=1`과 1단계 허용원금 등 시작상태를 **원자적으로 저장**하지만 주문 API를 호출하지 않습니다.

**시작 callback 자체에서 실제 주문은 0건이어야 합니다.** 첫 BUY는 이후 별도 안전주기에서 모든 조건을 처음부터 재검증한 뒤에만 가능합니다.

## 8. 최종 BUY 독립 안전경계

상위 계산이 잘못되더라도 실제 broker POST 직전 최종 경계에서 최소 다음을 독립적으로 다시 검사합니다.

- JH AUTO 실행계층 활성상태와 호환 버전
- 최초 시작승인 ON
- startup/system quarantine OFF
- 운영자 `/halt` latch OFF
- AUTO state `RUNNING`
- operator BUY halt OFF
- SAFE_MODE 없음
- 운용 기준자금·자동운용비율의 정상 범위
- `목표 자동원금 = 운용 기준자금 × 자동운용비율`
- `0 < 현재 허용원금 <= 목표 자동원금`
- HWM이 현재 허용원금 이상이고 HWM75 위험예산이 독립 재계산 상한 이하
- 현재 보유 + committed open BUY + 이번 주문이 목표수량을 넘지 않음
- managed cash·HWM75·브로커 매수가능금액 범위 안
- 활성 BUY/미체결 예약과 주문 멱등성 정상
- **실제 broker POST 직전 현재시각 기준 미국 정규장 여부**
- 실제 제출에 사용할 가격이 최신성 기준을 충족

하나라도 증명되지 않으면 BUY는 fail-closed입니다.

자동주기 시작시각이 정규장이었다는 이유만으로 주문하지 않습니다. 실제 POST 직전 현재시각을 다시 확인하며, 검토가 지연되어 정규장을 벗어나면 신규 BUY를 제출하지 않습니다.

## 9. 자동 BUY 실행 순서

기존 review → execution 2단계 검증코드를 우회하지 않습니다.

```text
활성 JDSS BUY 필요
→ review 생성·검증
→ 최신 가격·수량 계산
→ execution 검증
→ 최종 BUY 독립 안전경계
→ OrderManager
→ Toss
→ 주문감시
→ 원장 반영
→ 계좌·원장 재대조
```

정상 JH AUTO 운영에서는 이 두 내부 단계를 사람이 매 주문마다 Telegram에서 승인하지 않습니다.

한 깨끗한 안전주기에서 신규 BUY는 최대 **1건**만 제출합니다.

## 10. 주문시도 회로차단기

파일럿 단계의 반복 오류가 주문요청 폭주로 이어지지 않도록 다음 상한을 둡니다.

- 동일 신호 자동시도: **최대 3회 / UTC 일자**
- 전체 자동 BUY 시도: **최대 5회 / UTC 일자**
- 전체 상한 도달 시 신규 BUY 격리
- 주문 결과가 `UNKNOWN`이면 횟수 상한과 별개로 즉시 신규 BUY 격리

같은 주문을 자동 재전송해 상한을 우회하지 않습니다.

## 11. 오류와 재시도

조회 전용 GET의 명확한 일시 오류만 제한적으로 재시도할 수 있습니다.

계좌 상태를 바꾸는 주문 제출·취소는 결과가 불명확하면 blind retry하지 않습니다.

대표적인 차단상황:

- POST timeout
- broker receipt 불명확
- 주문결과 `UNKNOWN`
- 취소결과 불명확
- 브로커 주문 ID 불일치
- 계좌·원장 수량 불일치

이 경우 성공/실패를 추정하지 않고 실제 Toss 상태와 원장을 먼저 확인합니다.

## 12. SELL-first와 부분체결

목표 위험이 줄어들면 SELL을 BUY보다 먼저 처리합니다. SELL 주문상태 확정 → 체결 delta 원장반영 → broker/DB reconciliation이 정상이어야 다음 BUY가 가능합니다.

부분체결·미완료·`UNKNOWN`·취소확인 실패가 있으면 신규 BUY를 차단합니다. 부분체결 잔량을 같은 주문으로 즉시 blind replay하지 않습니다.

## 13. 세 종류의 정지

### 운영자 `/halt`

- 신규 BUY 즉시 차단
- durable operator latch ON
- 가능한 미체결 BUY 취소 시도
- 위험축소 SELL·주문감시·계좌대조는 가능한 범위에서 계속
- **시스템 자동해제 금지**

`/resume`은 운영자의 별도 2단계 확인과 계좌대조를 거쳐야 하며, 최초 `/auto start`와 다른 행위입니다.

### 시스템 임시격리

재시작·설정변경·내부 오류 시 시스템이 신규 BUY를 막는 상태입니다. 이미 최초 시작승인이 있고 미체결 0·계좌/원장 일치·SAFE_MODE 없음 등 정상상태를 증명한 경우에만 후속 독립 안전주기에서 자동복귀할 수 있습니다.

### SAFE_MODE

주문결과·브로커 상태·원장 상태를 확정할 수 없는 경우의 강한 안전정지입니다. 단 한 번의 정상조회만으로 성공을 추정하지 않습니다.

## 14. 자금설정 변경 중 보호

이미 최초 시작승인이 완료된 뒤 운용 기준자금이나 자동운용비율을 변경할 때는 첫 설정 write 전에 BUY 경계를 잠급니다.

```text
BUY halt ON
→ AUTO CONFIGURING / 시스템 임시격리
→ 자금·HWM·목표·성과단위 재계산
→ 계약 일관성 검사
→ 원자적 저장
→ 격리 유지
→ 다음 독립 안전주기에서 계좌·원장 재대조
→ 정상 증명 시에만 자동복귀
```

설정 callback 자체가 BUY를 다시 열지 않습니다. 중간 예외가 발생하면 격리상태를 유지합니다.

검토 버튼은 당시 자금·비율·허용원금·시작승인·단계·halt 상태와 설정 수정번호에 연결합니다. 값이 다시 같아졌더라도 설정 revision이 바뀌었으면 이전 버튼을 거부합니다.

## 15. 상태 저장 원자성

다음은 하나의 DB transaction 또는 동등한 원자경계로 저장합니다.

- 최초 시작승인
- 현재 허용원금
- 성과단위
- 최고 평가액/HWM 기준
- 자금 이벤트
- 목표 무효화와 관련 상태

중간 장애가 발생하면 부분 저장 상태에서 계속 운용하지 않습니다. 기존 버전에서 이미 손상된 승인·회계는 임의 초기화하지 않고 신규 BUY 차단 상태로 원장을 점검합니다.

## 16. 알림 장애와 scheduler 예외

Telegram 알림 전송 실패는 주문 실패로 취급하지 않습니다. 실패시각과 오류 종류를 기록하고 주문감시·계좌대조를 계속하며 주문을 재전송하지 않습니다.

예상하지 못한 scheduler 예외는 신규 BUY를 임시 차단하고 다음 점검주기에서 실제 계좌·원장부터 확인합니다. 안전상태 저장 자체가 불가능하면 외부 최근 동작시각 점검으로 장애를 탐지할 수 있어야 합니다.

## 17. 실제 Toss 계좌 운영원칙

- Toss 실제 보유·미체결·buying power가 최종 외부 사실입니다.
- 내부 원장과 계속 대조합니다.
- QQQ/TQQQ/SOXL을 JH AUTO와 Toss 앱에서 동시에 수동매매하지 않는 것이 운영 원칙입니다.
- 비관리 종목은 JH AUTO 목표·HWM·자동 SELL에 자동 포함하지 않습니다.
- 계좌조회 실패를 0주 또는 정상으로 해석하지 않습니다.

## 18. 배포·재시작 계약

첫 JH AUTO 배포 완료조건에는 프로그램·DB·Telegram·계좌 read-only가 정상이어도 다음 상태를 유지하는 것이 포함됩니다.

```text
launch_authorized = 0
현재 허용원금     = 0
신규 BUY          = 차단
```

이미 최초 시작승인이 완료된 계정의 코드 업데이트는 startup quarantine에서 시작합니다. 운영자 `/halt` latch는 보존하며, 안전조건을 모두 재증명한 경우에만 후속 안전주기에서 시스템 임시격리를 해제할 수 있습니다.

배포 작업은 `/auto start`, `/resume`, 기준자금 변경, 자동운용비율 변경을 수행하지 않습니다. 상세 배포·실계좌 연결·rollback은 [`infra/DEPLOYMENT.md`](infra/DEPLOYMENT.md)가 소유합니다.

## 19. Telegram 계약

운영자가 실제로 사용하는 명령·화면·메시지 표현 기준은 [`TELEGRAM_BOT_GUIDE.md`](TELEGRAM_BOT_GUIDE.md)가 소유합니다.

JH AUTO가 요구하는 핵심은 다음입니다.

- `/dashboard`: 전체 자동운용 상태·성과·자금·안전상태
- `/today`: 오늘 목표수량·자동매수/위험축소·차단이유
- `/auto`: 기준자금·자동운용비율·현재 허용원금·최초 시작
- `/account`: 실제 Toss 계좌
- `/portfolio`: 관리종목 보유·목표·수익률
- `/halt`: 운영자 긴급 신규 BUY 정지

정상 자동운전 중 운영자의 기본 행동은 **없음**입니다.

## 20. 필수 회귀테스트

JH AUTO 변경은 최소 다음을 검증합니다.

- 최초 배포 직후 시작 미승인·현재 허용원금 0·BUY 0
- 기준자금/비율 설정만으로 BUY 0
- `/auto start` callback 자체 주문 0
- 첫 BUY는 다음 독립주기에서만 가능
- 50→75→100 단계와 최소 3 거래세션·실제 체결증거
- 증액 시 추가분만 단계개방, 감액 즉시 위험축소
- 자금 유입·회수로 누적수익률 왜곡 없음
- 자금설정 변경 중 BUY halt·격리·원자성
- stale/재사용 callback 거부
- 운영자 `/halt` 자동해제 불가
- startup quarantine 안전조건 없이는 해제 불가
- 미국 정규장 외 신규 자동 BUY 0
- broker POST 직전 실제시각 재검사
- 한 안전주기 BUY 최대 1건
- 동일 신호 3회/UTC 일자, 전체 BUY 시도 5회/UTC 일자 상한
- 부분체결·UNKNOWN blind replay 없음
- 브로커↔원장 불일치 시 BUY 0
- 중복 scheduler에서도 중복주문 없음
- 알림 실패가 주문 재전송으로 이어지지 않음

## 21. 변경하지 않는 전략 영역

JH AUTO 1.0.0은 다음 JDSS 전략 수학을 소유하지 않습니다.

- SMA50 / SMA200
- 모멘텀 21 / 63 / 126
- 변동성 20일 / 30% 브레이크
- 노출 0.5 / 1.0 / 1.25 / 1.5
- SOXX RS6M
- 레버리지 sleeve 분할
- 최대 5% 추가 레버리지 판단
- HWM 이익 75% 재투자

이 영역을 바꾸려면 별도 전략 연구·백테스트·채택 절차를 거쳐 JDSS 전략 버전을 변경합니다.
