# JH AUTO 1.0.0 공식 자동운용 사양

이 문서는 **자동매매 실행·자금·성과·안전·운영 계약의 단일 기준**입니다.

투자판단 자체는 [`JDSS_FINAL_SPEC.md`](JDSS_FINAL_SPEC.md)의 **JDSS 3.2.2**가 소유합니다. JH AUTO는 전략을 바꾸지 않고, JDSS가 만든 목표를 실제 계좌에서 얼마만큼·어떤 안전조건으로 자동 실행할지를 관리합니다.

---

## 1. 버전체계

JH_HOLDINGS는 앞으로 두 버전을 구분합니다.

| 구분 | 현재 버전 | 책임 |
|---|---|---|
| 투자전략 | `JDSS 3.2.2` | 시장판단, 목표노출, QQQ/TQQQ/SOXL 목표비중, RS6M, HWM75 공식 |
| 자동매매 시스템 | `JH AUTO 1.0.0` | 위임자금, 자동운용비율, 자동승인, 주문실행, 안전정지, 성과회계, Telegram 통제 |

자동매매 코드가 바뀌었다는 이유만으로 JDSS 전략 버전을 올리지 않습니다. 반대로 향후 JDSS 전략이 3.3.x로 바뀌어도 JH AUTO가 그대로 호환된다면 자동매매 버전은 유지할 수 있습니다.

## 2. 자금 정의

JH AUTO는 다음 세 값을 분리합니다.

### 2.1 운용 기준자금

운영자가 Telegram에서 정하는 기준 원금입니다.

예:

```text
운용 기준자금 = $50,000
```

전략 파일의 과거 연구 기준자금 `$50,000`과 달리, JH AUTO의 운용 기준자금은 **운영설정**입니다. 코드나 `strategy.yaml`을 수정하지 않고 변경할 수 있습니다.

### 2.2 자동운용비율

운용 기준자금 중 JH AUTO에 맡길 비율입니다.

```text
자동운용비율 = 20%
```

1~100% 범위에서 운영자가 정합니다. 시스템이 스스로 올릴 수 없습니다.

### 2.3 목표 자동원금

```text
목표 자동원금 = 운용 기준자금 × 자동운용비율
```

예:

```text
$50,000 × 20% = $10,000
```

이 값은 “항상 시장에 $10,000을 투자한다”는 뜻이 아닙니다. JDSS가 0.5배 방어노출을 선택했다면 실제 시장투자 목표는 더 작을 수 있습니다.

### 2.4 현재 허용원금

목표 자동원금 중 현재 JH AUTO가 실제 위험예산 계산에 사용할 수 있도록 열린 원금입니다.

최초 시작이나 증액 과정에서는 `현재 허용원금 < 목표 자동원금`일 수 있습니다.

## 3. 최초 자금투입과 증액

새 위험은 한 번에 열지 않습니다.

### 3.1 최초 시작

목표 자동원금이 $10,000이라면:

```text
1단계 50%  → 현재 허용원금 $5,000
2단계 75%  → 현재 허용원금 $7,500
3단계 100% → 현재 허용원금 $10,000
```

단계 진행 조건:

1. 해당 단계의 JDSS 목표수량이 실제로 충족됨
2. 미체결 주문 0
3. 실계좌와 원장 일치
4. 안전정지 없음
5. 현재 단계 충족 후 최소 3 미국 거래세션 경과

시간만 지났다고 다음 단계로 가지 않습니다.

### 3.2 자동운용 원금 증액

기존 $10,000 → 새 목표 $25,000이면 **추가된 $15,000만** 50→75→100%로 엽니다.

기존 $10,000은 다시 축소하지 않습니다.

### 3.3 감액

자동운용비율이나 기준자금 감소로 목표 자동원금이 낮아지면 증액단계를 기다리지 않습니다. 새 허용원금으로 즉시 낮추고, 다음 목표계산에서 필요한 위험축소 매도를 우선 수행합니다.

위험감소는 지연하지 않고 위험증가만 단계적으로 진행합니다.

## 4. JDSS와 JH AUTO의 계산 경계

### JDSS 3.2.2가 결정하는 것

- QQQ 기반 시장추세
- 0.5 / 1.0 / 1.25 / 1.5배 노출
- SOXX 126거래일 상대강도
- QQQ/TQQQ/SOXL 목표비중
- 5% 추가 레버리지 판단
- HWM 수익재투자율 75%
- 완결봉 → 다음 거래일 실행 원칙

### JH AUTO 1.0.0이 결정하는 것

- 운용 기준자금
- 자동운용비율
- 현재 허용원금
- 자금 증액·감액 회계
- 실제 목표수량 산출에 사용할 현재 위험예산
- 자동검토·자동승인
- 실제 주문 순서
- 최초 시작승인
- 자동 임시격리와 대표 긴급정지
- 운영성과 계산과 Telegram 표시

JH AUTO는 JDSS 목표비중을 임의로 바꾸지 않습니다.

## 5. HWM75와 자금변경 회계

JH AUTO가 시작된 뒤 HWM75는 **실제 자동운용 원금과 실제 자동운용 자산**을 기준으로 계산합니다.

예:

```text
현재 허용원금 $10,000
최고 자동운용자산 $12,000
누적이익 $2,000
재투자 인정 75% = $1,500
위험예산 ≈ $11,500
```

외부자금 위임 증가·감소는 수익으로 보지 않습니다.

예:

```text
기존 허용원금 $10,000
현재 평가액 $12,000
기존 투자수익 $2,000

추가 위임 +$15,000
새 허용원금 $25,000
조정 HWM $27,000
```

기존 $2,000 수익만 유지됩니다.

## 6. 공식 수익률

### 6.1 포트폴리오 전체

기준자금이나 자동운용비율을 중간에 바꿔도 수익률이 왜곡되지 않도록 **단위가치 방식의 시간가중 성과**를 사용합니다.

외부자금이 들어오거나 빠질 때 현재 단위가치로 성과단위를 발행·회수합니다.

```text
누적수익률 = 현재 단위가치 / 시작 단위가치 - 1
```

Telegram에는 다음을 함께 표시합니다.

- 현재 자동운용자산
- 누적 운용손익
- 누적 운용수익률

### 6.2 종목별

종목별 화면의 `보유수익률`은 **현재 보유분의 평가손익 / 현재 보유분 원가**입니다.

종목별 수익률을 단순히 더해 전체 포트폴리오 수익률로 사용하지 않습니다.

## 7. 최초 시작승인: 가장 중요한 경계

JH AUTO를 코드로 배포했다고 자동매매가 시작되지 않습니다.

첫 배포 기본상태:

```text
JH AUTO 설치      완료
운용 기준자금      미설정 또는 운영자 설정값
자동운용비율       미설정 또는 운영자 설정값
최초 시작승인      OFF
현재 허용원금      $0
시스템 임시격리    ON
실제 신규 BUY      차단
```

### 7.1 시작 전 허용되는 것

- 시장데이터 조회
- 전략 계산
- 계좌 조회
- 계좌·원장 대조
- Telegram 표시
- 기준자금 설정
- 자동운용비율 설정

### 7.2 시작 전 금지되는 것

- 실제 신규 BUY
- 시작승인 자동생성
- 배포를 이유로 한 자동 시작
- 서버 재시작을 이유로 한 자동 시작

### 7.3 Telegram 최초 시작확인

`/auto start` 또는 시작 버튼은 2단계 확인을 사용합니다.

최종 확인 callback은 오직 `launch_authorized=1`과 1단계 허용원금을 기록합니다.

**해당 callback에서 주문 API를 호출하지 않습니다.**

첫 BUY는 이후 별도의 자동운용 주기에서 다음을 처음부터 다시 확인한 뒤에만 가능합니다.

```text
계좌·원장 대조
→ 미체결 0
→ UNKNOWN 없음
→ 안전정지 없음
→ 대표 긴급정지 없음
→ 미국 정규장
→ 최신 가격
→ 현재 JDSS 목표
→ 현재 허용원금/HWM75
→ 목표수량 재계산
→ 기존 주문경계 재검증
→ 실제 주문
```

## 8. 자동 BUY 실행 계약

JH AUTO는 기존 안전한 2단계 승인 코드를 우회하지 않습니다.

```text
활성 JDSS 매수신호
→ 검토 승인 생성
→ 최신 가격·수량 검증
→ 실행 승인 생성
→ 실행 직전 최신 가격·수량 재검증
→ OrderManager
→ Toss
```

차이는 사람이 Telegram 버튼을 누르는 대신 JH AUTO가 **안전주기 안에서 두 단계를 순차 소비**한다는 점입니다.

### 8.1 정규장 전용

JH AUTO 1.0.0의 신규 자동 BUY는 미국 정규장에서만 허용합니다.

장전·장후 자동 BUY는 1.0.0 범위에서 제외합니다.

### 8.2 한 안전주기 한 종목

한 번의 깨끗한 안전주기에서 자동 BUY는 최대 1건만 제출합니다.

```text
주문 1건
→ 주문감시
→ 계좌·원장 재대조
→ 정상 확인
→ 다음 안전주기
→ 다음 종목 가능
```

여러 종목을 동시에 제출하지 않습니다.

### 8.3 오래된 목표를 쫓지 않음

항상:

```text
최신 목표수량 - 실제 보유수량 - 이미 주문된 수량
```

을 다시 계산합니다.

예전 미승인 수량을 ‘남은 빚’처럼 쌓지 않습니다.

## 9. 오류와 재시도

### 자동 재시도 가능

조회 전용(GET) 작업의 명확한 일시 오류만 제한적으로 재시도할 수 있습니다.

예:

- 네트워크 일시 오류
- 429
- 5xx
- 읽기 전용 토큰 갱신 경합

### 자동 재전송 금지

계좌 상태를 바꾸는 주문/취소 요청은 결과가 불명확하면 자동 재전송하지 않습니다.

특히:

- POST timeout
- 주문결과 UNKNOWN
- broker order ID 불명확
- 취소 완료 불명확
- 계좌·원장 수량 불일치

에서는 추가 BUY를 차단하고 실제 상태 확인을 우선합니다.

## 10. 세 종류의 정지

### 10.1 대표 긴급정지

운영자가 `/halt` 실행.

- 신규 BUY 즉시 차단
- 활성 BUY 승인 취소
- 미체결 BUY 취소 시도
- 자동 위험축소·주문감시·계좌대조는 가능한 범위에서 계속
- **시스템이 절대 자동해제하지 않음**

`/resume`의 명시적 운영자 확인과 계좌대조를 거쳐야 해제됩니다.

### 10.2 시스템 임시격리

서버 시작·재시작 또는 자동운용 내부 오류 시 사용합니다.

- 신규 BUY 차단
- 대표 긴급정지와 별도 상태
- 이미 최초 시작승인이 있는 계정만 자동복귀 후보
- 미체결 0, 계좌·원장 일치, SAFE_MODE 없음 등을 증명한 경우에만 자동해제 가능

### 10.3 안전정지(SAFE_MODE)

주문결과 불명, 실제 수량불일치 등 상태를 확정할 수 없는 경우.

확실히 정상임을 증명하기 전 신규 BUY를 허용하지 않습니다.

## 12. Telegram 자금변경

예:

```text
/auto capital 50000
/auto ratio 20
/auto start
```

모든 자금·비율·최초시작 변경은 1회성 2단계 확인 callback을 사용합니다.

버튼이 만료되거나 서버가 재시작되면 확인 요청을 다시 만들어야 합니다.

진행 중 주문이 있거나 계좌·원장이 불일치하면 자금변경을 거부합니다.

시스템이 기준자금이나 자동운용비율을 스스로 높일 수 없습니다.

## 13. 배포 계약

코드 배포와 자동매매 시작은 별개입니다.

첫 JH AUTO 배포 완료조건:

```text
프로그램 정상
DB migration 정상
Telegram 정상
계좌 read-only 정상
JH AUTO version = 1.0.0
launch_authorized = 0
BUY halt = ON
실제 신규 BUY = 불가
```

사용자가 이후 Telegram에서 자금을 설정하고 최초 시작을 승인해야 합니다.

기존에 JH AUTO가 이미 시작된 계정의 일반 코드 업데이트는 startup quarantine부터 시작하며, 대표 긴급정지가 없고 안전조건을 모두 재증명한 경우에만 정상 자동운전으로 돌아갈 수 있습니다.

배포 작업 자체는 기준자금·자동운용비율·최초 시작승인을 임의로 바꾸지 않습니다.

## 14. 필수 테스트

JH AUTO 변경은 최소 다음을 회귀검증합니다.

- 설치 직후 최초 시작 미승인
- 기준자금만 설정해도 BUY 0
- 비율만 설정해도 BUY 0
- 시작 callback 자체 BUY 0
- 시작 후 다음 독립주기에서만 BUY 가능
- 50k / 20% → 목표 자동원금 10k
- 최초 1단계 → 5k 허용원금
- 증액 시 추가분만 50→75→100
- 감액 즉시 위험축소 목표
- 자금 유입·회수로 누적수익률 왜곡 없음
- 대표 `/halt` 자동해제 불가
- startup quarantine 안전조건 없이는 해제 불가
- 미국 정규장 외 신규 자동 BUY 0
- 한 안전주기 BUY 최대 1건
- 부분체결 후 blind 잔량 재주문 없음
- UNKNOWN 재주문 없음
- 브로커↔원장 불일치 시 BUY 0
- 중복 scheduler에서도 중복주문 없음
- 100% 자금에서는 같은 위험예산에서 기존 JDSS 목표수량 산식과 일치

## 15. 변경하지 않는 전략 영역

JH AUTO 1.0.0 도입은 다음을 전략변경으로 간주하지 않습니다.

- QQQ 기반 추세판단
- SMA50 / SMA200
- 모멘텀 21 / 63 / 126
- 변동성 20일 / 30% 브레이크
- 노출 0.5 / 1.0 / 1.25 / 1.5
- SOXX RS6M
- 레버리지 슬리브 분할
- 5% 추가 레버리지 판단
- HWM 이익의 75% 재투자
- 정수주 주문
- 자동 위험축소 SELL 우선

전략 자체를 바꾸려면 별도 전략 연구·백테스트·채택 절차를 거쳐 JDSS 전략 버전을 올립니다.
